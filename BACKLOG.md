## [BL-001] Семантический аудит карточек через Кодекс

**Статус:** идея, не реализована  
**Приоритет:** высокий  
**Дата:** 07.04.2026

### Проблема

Все 9 технических проверок при capture не ловят семантические ошибки:
- Qwen написал `Структурный элемент: статья 15`, а реально в документе нужна статья 21
- Поле `Значение для темы` написано общо, не привязано к конкретной подтеме

Это единственный незакрытый сценарий после полной антигаллюцинационной архитектуры.

### Решение

Новая команда в `notary_agent.py`: **`semantic-audit-part <subtopic_id> <part_number>`**

**Архитектура:** Codex — не параллельный research-агент, а **семантический верификатор** выхода Qwen. Работают последовательно: Qwen собирает Часть → capture проходит 10 шагов → `semantic-audit-part` передаёт карточки Кодексу → Кодекс проверяет → при ошибках Qwen переделывает.

**Алгоритм:**
1. Читает захваченный текст Части из `02-stage-outputs/`
2. Извлекает все карточки: URL2 + Структурный элемент + Значение для темы
3. Формирует промпт и передаёт Кодексу автоматически (без ручных шагов пользователя)
4. Кодекс делает реальный `web_fetch` каждого URL2:
   - Структурный элемент существует в документе?
   - «Значение для темы» конкретно для подтемы?
5. Возвращает структурированный отчёт: `OK` / `ОШИБКА СТРУКТУРНОГО ЭЛЕМЕНТА` / `СЛАБОЕ ЗНАЧЕНИЕ`
6. При ошибках — Qwen переделывает карточки, повторный capture (10 шагов)

**Схема:**

```
┌─────────────────────────────────────────────────────────────┐
│                        ПОДТЕМА X                            │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│                    QWEN — Фаза 1–3                          │
│  run-subtopic → web-plan → launch-packet                    │
│  LLM: web_search → web_fetch → карточки                     │
│  capture: 10 шагов (RuntimeError при нарушении)             │
└─────────────────────────────────────────────────────────────┘
                            │
                    ✅ capture прошёл
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│         semantic-audit-part (notary_agent.py)               │
│                                                             │
│  Читает захваченный текст Части                             │
│  Извлекает карточки: URL2 + Структурный элемент +           │
│                       Значение для темы                     │
│  Формирует промпт → передаёт Кодексу                        │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│                  CODEX — Семантический аудит                │
│                                                             │
│  Для каждой карточки:                                       │
│    web_fetch(URL2)                                          │
│    ├── Структурный элемент существует в документе?          │
│    └── «Значение для темы» конкретно для подтемы?           │
│                                                             │
│  Возвращает отчёт:                                          │
│    OK │ ОШИБКА СТРУКТУРНОГО ЭЛЕМЕНТА │ СЛАБОЕ ЗНАЧЕНИЕ      │
└─────────────────────────────────────────────────────────────┘
                            │
              ┌─────────────┴─────────────┐
              │                           │
           ОШИБКИ                        OK
              │                           │
              ▼                           ▼
┌─────────────────────────┐   ┌──────────────────────────────┐
│  Qwen переделывает      │   │  Часть принята               │
│  карточки → повторный   │   │  Переход к следующей Части   │
│  capture (10 шагов)     │   └──────────────────────────────┘
└─────────────────────────┘
```

**Плюсы:**
- Кодекс имеет нативный `web_fetch` — может реально открыть каждый URL2
- Закрывает последний незакрытый семантический пробел (структурный элемент + значение для темы)
- Пользователь не участвует — всё автоматически

**Файлы для изменения:**
- `Notary Qwen/notary_agent.py` — новая команда `cmd_semantic_audit_part`
- `Notary Qwen/AGENTS.md` — описание команды
- Возможно: аналогичная команда в `Notary document research agent/notary_agent.py`
