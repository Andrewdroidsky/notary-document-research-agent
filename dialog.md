## Сессия 07.04.2026 (продолжение) — WebFetch Protocol для Qwen и Codex

### Контекст

Во второй половине той же сессии пользователь предложил три дополнительных требования, полностью закрывающих последний коридор для галлюцинации — Qwen генерирует текст Части до/вместо tool call. Реализация: обязательные inline-маркеры прямо в теле ответа, валидируемые при захвате.

### Три требования пользователя (WebFetch Protocol)

1. **`[WEBFETCH-ДЕКЛАРАЦИЯ]`** — объявляет перед поиском, что все ссылки будут получены через web_fetch. Прямо в начале текста Части.
2. **`Продолжаю верификацию через web_fetch`** — прогресс-маркер, inline в тексте Части, после каждой карточки (или группы). Считается поисковым маркером в 1:1-счётчике.
3. **`[WEBFETCH-ПОДТВЕРЖДЕНИЕ]`** — подтверждение в конце текста Части: все URL2 получены через web_fetch, заголовки совпадают.

**Ключевое архитектурное решение:** маркеры должны быть ВНУТРИ текста Части — тогда они попадают в захват и могут быть проверены автоматически. Если Qwen пишет их только в чате — захват пройдёт без них и ValidationError заблокирует.

`check_search_grounding` переведён из advisory в `RuntimeError`:

- Маркер `Продолжаю верификацию через web_fetch` добавлен в `SEARCH_DECLARATION_RE` как полноправный маркер поиска.
- Ни одна карточка без предшествующего маркера. Ни одного шанса.

### Реализация в Qwen `notary_agent.py`

**Константы:**
- `WEBFETCH_MANDATE` — полный текст мандата с примерами обоих маркеров.

url2_pattern = re.compile(r"^URL2:\s*`(https?://[^`]+)`", re.MULTILINE)

## Сессия 08.04.2026 (продолжение 11) — Smart MISMATCH: parent-document check + инструкция

### Контекст

В 16.13.1 Часть 5 дала 3 MISMATCH подряд. Корень: Qwen указывал URL2 на весь кодекс/закон, `_titles_match` сравнивал «Статья 311 ГПК РФ» с «Гражданский процессуальный кодекс...» → MISMATCH. Технически верно, но приводило к фрустрации и массовому обходу протокола (Parts 6–11 без fetch-and-log).

### Решение

**1. Parent-document check в `_titles_match`.**  
Если в claimed есть «Статья N», а заголовок реальной страницы — родительский документ того же кодекса/закона (совпадение по `_DOC_CODE_RE` или `_LAW_NUM_RE`) → результат `True` (PARENT_DOC, не MISMATCH).

**2. MISMATCH-инструкция в WEBFETCH_MANDATE.**  
При MISMATCH Qwen видит прямо в тексте ошибки: «причина — URL на весь документ; решение — URL на конкретную статью с якорем-хэшем».

| Нет инструкции по исправлению | MISMATCH содержит объяснение и пример |
