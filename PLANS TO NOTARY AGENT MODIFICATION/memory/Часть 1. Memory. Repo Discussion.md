## Ключевые инсайты сессии

### Терминологическая путаница агенты vs субагенты
Пользователь правильно заметил: то что в репо называется "agents" — это конфигурации/инструкции (субагенты). Настоящий агент — сам Claude Code, который порождает внутренние субагенты. Сообщество использует термины неточно.

### Хуки vs субагенты
Пользователь не знал о хуках и был впечатлён тем, что хуки работают независимо от агента, не тратят токены и maxTurns. Ключевой инсайт: хук может заблокировать действие агента через exit code ≠ 0.

### settings.json = точка входа системы
Вся система Claude Code настраивается через settings.json. Именно там подключаются все 27 хуков к скрипту hooks.py, задаются разрешения (allow/deny/ask), интерфейс.

### Порядок приоритетов настроек
1. `--model opus` (CLI флаги)
2. `.claude/settings.local.json` (проект, личный)
3. `.claude/settings.json` (проект, командный)
4. `~/.claude/settings.local.json` (глобальный личный override)
5. `~/.claude/settings.json` (глобальный default)
6. `managed-settings.json` (организационная политика)

`~` = `C:\Users\koper\` на Windows.

### Оркестрация
- Оркестратор = диспетчер (сам не делает, координирует)
- Субагент получает данные через промпт при вызове — промпт должен быть самодостаточным
- Независимые задачи — параллельно, зависимые — последовательно
- `bypassPermissions` опасно, лучше `allowedTools`

### Архитектура weather-оркестратора
```
/weather-orchestrator → weather-agent (+ preloaded: weather-fetcher) → Open-Meteo API
                     → weather-svg-creator (скилл напрямую)
```
Два типа скиллов: preloaded (встроен в агента) и invoked (вызывается напрямую командой).

### Хуки в репо = звуковые уведомления
`hooks.py` проигрывает разные WAV-звуки на каждое событие. Поддержка Windows/Mac/Linux. Лог событий в `hooks/logs/hooks-log.jsonl`.

### GitHub API в репо
Используется для автоматического мониторинга 10 чужих репозиториев и обновления сравнительной таблицы в README.md командой `/development-workflows`.

## Сводная таблица сущностей Claude Code

| Сущность | Что делает | Когда срабатывает |
|----------|-----------|-------------------|
| **CLAUDE.md** | Общие инструкции для проекта | Всегда |
| **rules** | Инструкции по glob-паттерну файлов | При работе с нужными файлами |
| **hooks** | Автоматические действия на события | Автоматически, без агента |
| **skills** | Переиспользуемые шаблоны | Когда агент/команда вызывает |
| **commands** | Slash-команды | Когда пользователь вводит |
| **agents** | Конфигурации субагентов | Когда оркестратор поднимает |
| **subagents** | Дочерние агенты | Когда агент делегирует |
| **settings.json** | Настройки Claude Code | При запуске сессии |
| **memory** | Память между сессиями | В начале каждой сессии |
| **MCP** (Model Context Protocol) | Подключение внешних инструментов | При вызове mcp__* |
| **LSP** (Language Server Protocol) | Интеграция с IDE | В VS Code / JetBrains |
| **plugins** | Расширения (часто через MCP) | При подключении |
| **status line** | Строка статуса интерфейса | Постоянно |
| **custom agents** | Пользовательские агенты | По имени или автоматически |

**Кто инициирует:**
- Пользователь → commands, MCP вручную
- Claude → agents, subagents, skills
- Система → hooks, rules, CLAUDE.md, LSP, status line
