**User:** а что такое хуки?

**User:** что конкретно они делают в репо?

**User:** а зачем хуки? Почему не использовать subagents?

**Claude:** Хуки и субагенты — разные инструменты для разных задач:

**Хуки** срабатывают **автоматически** на системные события, не требуя решения агента. Агент не знает о них — они работают снаружи, параллельно.

**Субагенты** — агент сам решает когда их вызвать, это часть его логики.

Для звуков хук идеален — зачем тратить токены и ходы агента (`maxTurns`) на воспроизведение звука? Хук делает это бесплатно, мгновенно, всегда — даже если агент упал с ошибкой.

**User:** это ценно - не знал. Хук только для звука применяется?

- **Логирование** — записывать все действия агента в файл

Ключевое преимущество — работают **независимо от агента**, не тратят его токены и ходы.

**User:** Система → hooks, rules, CLAUDE.md - какая Система? Как она представлена/выражена в репо?

**Claude:** "Система" — это сам **Claude Code** (движок). В репо она выражена через **`settings.json`** — главный конфигурационный файл. Именно он говорит системе:
- **Хуки** — на какие события и какой скрипт запускать (все 27 событий привязаны к `hooks.py`)
- **Разрешения** — что Claude может делать без спроса (`allow`), что запрещено (`deny`), что требует подтверждения (`ask`)
- **Интерфейс** — кастомные тексты спиннера, статус-строка, стиль ответов
- **Окружение** — переменные среды

`settings.json` — это и есть точка входа системы. Всё остальное (агенты, скиллы, команды) работает через него.

**User:** что в этом репо отвечает за оркестрацию?

**Claude:** За оркестрацию отвечает **`/weather-orchestrator`** (команда). Вся схема:

```
/weather-orchestrator (команда-оркестратор)
    ├── Спрашивает пользователя: Celsius или Fahrenheit?
    ├── → weather-agent (агент + preloaded скилл weather-fetcher)
    │       └── Fetches температуру из Open-Meteo → возвращает число
    └── → weather-svg-creator (скилл)
            └── Создаёт SVG карточку и output.md
```

Два типа скиллов:
- `weather-fetcher` — **preloaded** в агента (знание встроено в контекст агента при старте)
- `weather-svg-creator` — **вызывается напрямую** командой через Skill tool

**User:** в чем цель и роль оркестратора в репо вообще?

**Claude:** Оркестратор — это **диспетчер**. Он сам ничего не делает, но координирует других:
1. **Принимает запрос** от пользователя
2. **Разбивает** задачу на части
3. **Делегирует** каждую часть нужному агенту или скиллу
4. **Собирает результаты** и возвращает пользователю

По сути это **автоматизация координации** — чем сложнее задача и больше участников, тем ценнее оркестратор.

**User:** Что еще учесть и на что еще обратить внимание при оркестрации?

**Claude:** Ключевые моменты при оркестрации:

**Контекст и токены**
- Каждый субагент имеет свой изолированный контекст — он не видит историю главного агента
- Передавай субагенту только нужные данные, не весь разговор

**Параллельность**
- Независимые задачи запускай параллельно (как в `development-workflows` — 2 агента одновременно)
- Зависимые задачи — строго последовательно

**maxTurns**
- Ставь разумный лимит — бесконечный агент может зациклиться и сжечь токены

**Возврат данных**
- Субагент должен вернуть чёткий структурированный результат — оркестратор не должен угадывать что получил

**Ошибки**
- Предусмотри что делать если субагент упал — оркестратор должен это обработать

**permissionMode**
- `bypassPermissions` у субагента — опасно, давай только нужные инструменты через `allowedTools`

**Главное правило:** оркестратор координирует, субагенты исполняют — не смешивай роли.

**User:** Передавай субагенту только нужные данные, не весь разговор - как передавать? Каким образом?

**Claude:** Через **промпт при вызове агента**. Когда оркестратор поднимает субагента, он передаёт ему текстовое сообщение с нужными данными.

В `development-workflows.md` это видно явно — команда передаёт агенту список конкретных репозиториев:

```
> Research these 3 Claude Code workflow repositories:
> **Repo 1: github/spec-kit** (https://github.com/github/spec-kit)
> ...
```

Субагент получает только этот промпт — он не знает ничего про весь предыдущий разговор. Именно поэтому промпт должен быть **самодостаточным** — содержать всё что нужно агенту для работы.
